# Point of view

These guidelines describe how to address readers and when to refer to <company>.

## Address the reader as "you"

- **keywords**: writing, grammar, point of view, second person, "you"  
- **content sets**: documentation, tutorials

Write in the second person by addressing the reader as "you" when describing actions that you expect the reader to perform. You can also directly tell readers to perform actions when providing instructions.

### Examples

**Do:**

- `In this tutorial, you allowed services to communicate with each other by configuring <product>.`
- `<product>'s API lets you create workspaces without a version control connection.`


**Don't:**

- `Upon completing this tutorial, a user has learned to allow services to communicate with each other by configuring <product>.`
- `We can use <product>'s API to create workspaces without a version control connection.`


## Use the inclusive "we" when speaking on behalf of <company>

- **keywords**: writing, grammar, point of view, "we", <company>  
- **content sets**: documentation, tutorials

Use the inclusive "we" when providing recommendations from <company> or when describing actions by the company. Alternatively, you can also use "<company>" in place of "we" when referring to guidance from the company. 

### Examples

**Do:**

- `We recommend configuring VCS access when first setting up an organization.`
- `We fixed a vulnerability where some users were able to copy their session cookie from the browser bar and use it in the API to continue a session.`
- `<company> is not responsible for compromised data if you do not use production-ready configurations.`

**Don't:**

- `In this example, we take the values from the previous step and add them to the configuration.`


## Do not use the inclusive "we" or personal possessives to guide readers through examples

- **keywords**: writing, grammar, point of view, "we", examples  
- **content sets**: documentation, tutorials

Do not refer to "our configuration" or describe actions "we" will take in documentation unless referring to artifacts provided by, or actions performed by, <company>. 

### Examples

**Do:**

- ``Add the `<product>` block to your `main.conf` file.``

**Don't:**

- `We will add the <product> block to our main.conf file.`
